# 软件课程设计 I 要求与安排

> 根据《2026年 软件课程设计I要求和安排》整理，供项目规划及 Codex
> 开发时参考。

## 1. 课程设计目的与意义

### 目的

将已学习的以下知识融会贯通、整理、提升和扩展：

-   编程技术
-   数据库技术（MySQL、MS SQL Server 等）
-   软件工程需求分析
-   软件设计与测试方法
-   数据库访问技术

### 意义

-   课程具有较高的综合性、设计性要求
-   培养分析能力和动手实践能力
-   培养团队协作能力
-   增强学习主动性

------------------------------------------------------------------------

## 2. 技术要求

项目应体现 **MVC 设计模式**以及 **J2EE 多层架构思想**。

### 数据访问层

-   使用数据库编程 SQL
-   数据访问框架采用以下之一：
    -   Hibernate
    -   MyBatis

### 业务逻辑层

-   使用 Java 编程
-   实现系统核心业务逻辑

### 表示层

-   至少采用一种主流前端框架

### 特别要求

-   不允许只制作静态网页
-   必须具有数据后端

------------------------------------------------------------------------

## 3. 项目组织

-   课题自拟
-   每组 1～3 名同学
-   确定小组成员和组长
-   同一教学班内可以跨班组队
-   在 QQ 群共享文档中填写课题信息

------------------------------------------------------------------------

## 4. 项目实施阶段

### 阶段一：确定课题

确定：

-   小组成员
-   组长
-   项目题目

### 阶段二：需求分析与设计

梳理项目具体需求并完成需求分析。

需要编写详细设计说明书，包括：

-   功能需求描述
-   数据库设计
    -   E-R 图
    -   表结构
-   系统结构
-   主要模块功能
-   用例图
-   场景图等

**阶段成果：**

《需求分析与详细设计书》，格式参考课程群文件模板。

### 阶段三：编码实现

完成与需求相符合并且能够正常运行的源代码。

建议：

-   使用 IDE
-   使用自动化工程编译/部署工具
-   建立单元测试思想
-   进行功能测试
-   有能力可考虑性能测试

**阶段成果：**

打包后的源程序，其中需要：

-   包含数据库设计 SQL 文件
-   包含项目所需第三方依赖
-   能够方便地直接部署运行

### 阶段四：优化与报告

完成：

-   系统优化
-   课程设计总报告
-   个人小结

最终提交：

-   设计报告
-   个人小结
-   打包后的源程序

预计提交时间为 **9 月中下旬**，具体以课程群通知为准。

### 阶段五：演示与答辩

-   每组派至少一名代表演示程序
-   回答教师提出的问题
-   可以由多名组员共同回答

------------------------------------------------------------------------

# 7. 需求分析要求

需求分析的核心目标是从软件开发人员视角清晰描述课题，回答：

1.  系统要做什么？
2.  系统的用户是谁？
3.  每个用户可以完成哪些功能？
4.  每个功能需求具体如何规定？
5.  系统有哪些非功能性需求？

------------------------------------------------------------------------

## 7.1 系统角色识别

需要识别目标系统的所有使用者。

针对本项目"足球票务与俱乐部管理系统"，后续可重点分析：

-   普通用户 / 球迷
-   俱乐部管理员
-   系统管理员

> 上述足球系统角色属于项目规划建议，并非课程 PPT
> 给出的固定要求，应根据最终需求方案确认。

------------------------------------------------------------------------

## 7.2 功能性需求识别

从使用者视角描述：

> 使用者通过目标系统能够完成哪些业务。

需要汇总不同角色的功能需求，并形成整个系统的业务功能概览。

------------------------------------------------------------------------

## 7.3 功能性需求规定

重要业务需要给出详细的 **用例描述** 和 **业务场景分析**。

每个核心用例建议描述：

  项目           内容
  -------------- ------------------------
  用例名称       功能名称
  实现名称       对应实现
  用例描述       该业务解决什么问题
  参与者         哪些角色参与
  前置条件       执行前需要满足什么
  后置条件       执行后系统发生什么变化
  主事件流       正常业务执行步骤
  备选事件流     异常或其他情况
  业务规则       业务约束
  涉及业务实体   使用哪些实体
  非功能性需求   性能、安全等要求

核心业务还应进行场景分析，可以使用 UML
活动图等方式表示角色与系统之间的业务过程。

------------------------------------------------------------------------

## 7.4 业务实体分析

分析特定业务实现过程中涉及的实体以及实体之间的关系。

对于足球票务系统，后续可能涉及：

-   用户
-   俱乐部
-   比赛
-   球场
-   票种
-   球票
-   订单
-   订单明细

> 具体实体以最终需求分析为准。

------------------------------------------------------------------------

## 7.5 非功能性需求

### 性能需求

例如：

-   并发用户数量
-   系统响应时间

### 安全需求

例如：

-   信息加密
-   登录认证

### 外部接口需求

根据项目实际情况进行分析。

------------------------------------------------------------------------

# 8. 系统设计要求

系统设计需要根据需求分析结果，设计能够指导后续编码实现的软件中间制品。

系统设计一般包括：

-   概要设计
-   详细设计

主要内容：

1.  软件架构设计
2.  功能模块设计
3.  用户界面设计
4.  数据库设计

------------------------------------------------------------------------

## 8.1 软件架构设计

课程要求采用基于 **MVC** 的软件架构。

基本结构：

``` text
用户
 ↓
表示层
Controller / View
 ↓
业务逻辑层
Service / Model
 ↓
数据访问层
Mapper / DAO
 ↓
数据库
```

实际项目开发时，应体现清晰的分层结构。

------------------------------------------------------------------------

## 8.2 功能模块设计

功能模块应：

> 围绕业务需求进行组织。

需要根据不同业务划分系统模块，并说明各模块包含的功能。

对于每一个重要功能点，还需要：

-   按 MVC 模式列出实现该功能所需的各种资源
-   使用统一的资源命名方式
-   给出业务逻辑过程
-   绘制 UML 序列图
-   完成具体类设计

------------------------------------------------------------------------

## 8.3 用户界面设计

界面设计目标：

> 使用户在完成任务时与系统之间的交互尽可能简单。

实现方式：

-   使用图形设计工具绘制简单界面原型
-   使用开源前端框架搭建界面
-   梳理各页面之间的跳转关系

------------------------------------------------------------------------

# 9. 数据库设计要求

数据库可选择：

-   MySQL
-   MS SQL Server
-   TiDB 等

建议本项目采用：

`MySQL`

数据库设计需要包含两个层面。

## 9.1 逻辑结构设计

来源于需求分析阶段的实体分析。

需要提供：

-   E-R 图

或：

-   数据库 UML 图

## 9.2 物理结构设计

需要给出完整表结构，包括：

-   字段名
-   字段类型
-   字段约束
    -   Primary Key
    -   Foreign Key
    -   Check 等
-   字段说明
-   表之间的关系
-   外键关系

------------------------------------------------------------------------

# 11. 推荐项目技术栈（项目建议）

结合课程要求，足球票务与俱乐部管理系统可以采用：

``` text
前端
Vue 3
Element Plus
Axios
Vue Router
Pinia

后端
Java 17
Spring Boot 3
Spring MVC
MyBatis-Plus

数据库
MySQL 8

构建
Maven

版本控制
Git
```

其中：

-   Spring Boot / Spring MVC 用于体现 MVC 与 Java 业务逻辑层

-   MySQL 满足数据库要求
