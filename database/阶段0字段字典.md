# 阶段0字段字典补充

本文件记录阶段6开始前经确认的阶段0设计基线最小修正。未列出的表继续以 `schema.sql` 和已确认的阶段0设计为准。

## match_info

| 字段名 | SQL类型 | 可空 | 主键 | 外键/约束 | 默认值 | 说明 |
|---|---|---|---|---|---|---|
| match_id | BIGINT UNSIGNED | 否 | 是 | — | AUTO_INCREMENT | 比赛主键 |
| season_id | BIGINT UNSIGNED | 否 | 否 | FK → season_info.season_id | — | 所属赛季 |
| round_id | BIGINT UNSIGNED | 否 | 否 | 复合FK → round_info(round_id, season_id) | — | 所属轮次 |
| home_club_id | BIGINT UNSIGNED | 否 | 否 | FK → club_info.club_id | — | 主队俱乐部 |
| away_club_id | BIGINT UNSIGNED | 否 | 否 | FK → club_info.club_id；与主队不同 | — | 客队俱乐部 |
| stadium_id | BIGINT UNSIGNED | 否 | 否 | FK → stadium_info.stadium_id | — | 比赛场馆 |
| match_time | DATETIME | 否 | 否 | — | — | 开赛时间 |
| sale_start_time | DATETIME | 是 | 否 | — | NULL | 全场售票开始时间，后续票务阶段使用 |
| sale_end_time | DATETIME | 是 | 否 | 不早于 sale_start_time | NULL | 全场售票停止时间，后续票务阶段使用 |
| home_score | INT UNSIGNED | 是 | 否 | 与 away_score 同时为空或同时非空 | NULL | 主队比分 |
| away_score | INT UNSIGNED | 是 | 否 | 与 home_score 同时为空或同时非空 | NULL | 客队比分 |
| match_status | VARCHAR(20) | 否 | 否 | DRAFT/PUBLISHED/IN_PROGRESS/FINISHED/CANCELLED | DRAFT | 比赛状态 |
| published_at | DATETIME | 是 | 否 | — | NULL | 首次从 DRAFT 进入 PUBLISHED 的时间，后续不得覆盖 |
| created_at | DATETIME | 否 | 否 | — | CURRENT_TIMESTAMP | 创建时间 |
| updated_at | DATETIME | 否 | 否 | — | CURRENT_TIMESTAMP，更新时刷新 | 更新时间 |

`match_info` 不设置赛季主客队组合唯一约束。明显重复比赛由业务层按赛季、轮次、主队和客队校验。

## ticket_order（阶段10确认补充）

| 字段名 | SQL类型 | 可空 | 主键 | 外键/约束 | 默认值 | 说明 |
|---|---|---|---|---|---|---|
| cancel_reason | VARCHAR(32) | 是 | 否 | Service控制合法值 | NULL | 取消原因；阶段10使用 USER_CANCELLED、PAYMENT_TIMEOUT，未取消时为NULL |

`cancel_reason` 不复用 `remark`。为降低后续新增系统取消原因时的迁移成本，本字段不增加数据库CHECK，由订单Service统一控制。

## order_item（阶段10确认补充）

| 字段名 | SQL类型 | 可空 | 主键 | 外键/约束 | 默认值 | 说明 |
|---|---|---|---|---|---|---|
| item_status | VARCHAR(16) | 否 | 否 | CHECK：LOCKED/PAID/CANCELLED/REFUNDED | LOCKED | 订单明细状态；阶段10仅产生LOCKED和CANCELLED |

完整状态基线为 `LOCKED`、`PAID`、`CANCELLED`、`REFUNDED`。阶段10创建订单写入 `LOCKED`，用户取消或支付超时执行 `LOCKED → CANCELLED`；`PAID` 和 `REFUNDED` 分别留待支付、退票阶段实现。

## checkin_record（阶段13确认修正）

| 字段名 | SQL类型 | 可空 | 主键 | 外键/约束 | 默认值 | 说明 |
|---|---|---|---|---|---|---|
| check_result | VARCHAR(24) | 否 | 否 | CHECK：SUCCESS/CODE_NOT_FOUND/WRONG_MATCH/ORDER_INVALID/TICKET_USED/TICKET_REFUNDED/TICKET_VOID | — | 本次检票尝试结果；成功和业务核验失败均保留记录 |

正式检票结果不再使用 `INVALID`、`ALREADY_USED`、`VOID_TICKET`。`scanned_ticket_code`、外键和索引保持原设计不变。
