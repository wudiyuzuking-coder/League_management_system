## 模块覆盖

- 认证：注册、四角色登录、`/api/auth/me`、JWT、401/403和数据权限。
- 俱乐部：ADMIN与CLUB管理边界，球员、教练、球衣号唯一及赛季统计。
- 联赛与比赛：赛季、轮次、积分榜、比赛状态、比分和发布时间。
- 场馆与票务：静态票区、物理座位、批量生成、比赛票区、独立库存与实时可售统计。
- 连坐：1至4张、同排连续、排序规则、最大连续数、无解和并发竞争。
- 订单：事务锁座、取消、超时、越权、回滚与并发终态。
- 支付与电子票：FAILED后SUCCESS、重复/并发支付、事务回滚、唯一电子票和SOLD锁字段清理。
- 退票：整单申请、审核、幂等、并发审核、退票与检票竞争。
- 检票：准确失败枚举、成功入场、重复/并发检票、主场权限和记录查询。
- 统计：销售、退款、票务、上座、趋势、热门比赛及CLUB数据范围。

## 真实HTTP与浏览器验收

真实构建产物 `league-ticket-backend-0.0.1-SNAPSHOT.jar` 在隔离库启动，Vue dev服务通过 `/api` 代理访问该JAR。

流程A（购票并入场）通过：新注册USER浏览赛季和已发布比赛，选择开售票区，创建2张订单并支付成功，生成2张电子票；CHECKER对两张票检票均返回SUCCESS；USER再次查询两张票均为USED。数据库显示订单与明细PAID、库存SOLD且锁字段全部为空。

流程B（购票并退票）通过：USER创建2张订单并支付，申请整单退票后状态为PENDING；ADMIN审核通过后，订单和2条明细均REFUNDED，2张电子票均REFUNDED，2个比赛库存均恢复AVAILABLE。

浏览器实际验证四种角色默认入口、菜单隔离、详情页菜单高亮、刷新认证恢复、403和404页面。ADMIN管理链路与CLUB/CHECKER页面对应接口均返回200。

## 数据一致性与性能

九项一致性查询全部返回0：待支付无锁座、已支付库存非SOLD、已支付明细非PAID、订单票数与电子票数不一致、已退票仍SOLD、已退票仍UNUSED、USED票关联非PAID订单、LOCKED无订单ID、锁订单ID归属错误。
