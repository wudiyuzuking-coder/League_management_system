# 阶段0字段字典补充

本文件记录阶段6开始前经确认的阶段0设计基线最小修正。未列出的表继续以 `schema.sql` 和已确认的阶段0设计为准。

## sys_user（阶段17A/17B/17C补充）

阶段17B以后，`user_id`是稳定身份主键，`phone`是全局唯一登录手机号，`username`是允许重复和修改的昵称。数据库中的`display_name`由后端映射为`realName`；`employee_no`独立保存管理人员工号。阶段17C增加`avatar_url`保存头像相对访问路径，图片文件不进入数据库。阶段20B1使用独立`club_apply_name`保存CLUB申请名称，负责人姓名继续单独存于`display_name`。

| 字段名 | SQL类型 | 可空 | 主键 | 外键/约束 | 默认值 | 说明 |
|---|---|---|---|---|---|---|
| user_id | BIGINT UNSIGNED | 否 | 是 | AUTO_INCREMENT | — | 稳定身份主键；JWT subject |
| username | VARCHAR(50) | 否 | 否 | 普通索引，可重复 | — | 昵称/展示名称，可由用户修改，不用于登录 |
| phone | VARCHAR(20) | 是 | 否 | UNIQUE | NULL | 唯一登录手机号；新建和启用时业务层必填 |
| display_name | VARCHAR(80) | 否 | 否 | — | — | 后端`realName`对应字段 |
| club_apply_name | VARCHAR(100) | 是 | 否 | — | NULL | CLUB注册申请时提交的俱乐部名称，仅用于审核阶段；其他角色为NULL |
| employee_no | VARCHAR(16) | 是 | 否 | UNIQUE | NULL | EVENT_ADMIN使用`EA####`，ADMIN使用`SA####`；USER/CLUB保持NULL |
| avatar_url | VARCHAR(255) | 是 | 否 | — | NULL | 头像相对访问路径，如`/uploads/avatars/{uuid}.png`；NULL使用默认头像 |
| club_id | BIGINT UNSIGNED | 是 | 否 | FK → club_info.club_id；UNIQUE | NULL | CLUB账号绑定的唯一负责俱乐部；一个俱乐部最多一个负责人 |

历史管理账号允许`employee_no`暂时为NULL，但业务层在新建、编辑或启用管理账号时要求真实姓名和合法工号。数据库唯一约束允许多个NULL，并作为并发情况下的最终唯一性防线。

## club_info（阶段20B1补充）

`home_city`调整为可空。NULL表示CLUB注册审核自动创建俱乐部后，负责人尚未完善所在地信息；数据库禁止写入“待完善”“未知”等占位语义。ADMIN原手工创建接口仍要求城市必填，CLUB后续通过原资料维护接口补齐。

| 字段名 | SQL类型 | 可空 | 主键 | 外键/约束 | 默认值 | 说明 |
|---|---|---|---|---|---|---|
| home_city | VARCHAR(50) | 是 | 否 | — | NULL | 俱乐部所在城市；审核自动创建时允许为空，后续由负责人补充 |

## season_info（阶段16B补充）

现有 `start_date/end_date` 保持 `DATE`，分别表示赛季比赛阶段开始和结束日期，并按闭区间判断报名赛季冲突。历史赛季允许以下新增字段为NULL；通过正常业务接口新建或修改赛季时三者必须完整提供。

| 字段名 | SQL类型 | 可空 | 主键 | 外键/约束 | 默认值 | 说明 |
|---|---|---|---|---|---|---|
| registration_start_time | DATETIME | 是 | 否 | 不晚于报名截止 | NULL | 报名窗口开始，资格判断使用统一系统时间 |
| registration_deadline | DATETIME | 是 | 否 | 不早于报名开始 | NULL | 报名窗口结束，截止时刻本身不可报名 |
| max_clubs | INT UNSIGNED | 是 | 否 | 1至20 | NULL | 最大报名俱乐部数 |

## club_season_enrollment_player（阶段16B新增）

保存报名阵容和报名时快照。`enrollment_id + player_id` 唯一，同一报名内非NULL球衣号码唯一；位置沿用 `GOALKEEPER/DEFENDER/MIDFIELDER/FORWARD`，阵容角色为 `STARTER/SUBSTITUTE`。

主要字段：`enrollment_player_id`、`enrollment_id`、`player_id`、`lineup_role`、`player_name_snapshot`、`shirt_no_snapshot`、`position_snapshot`、`birth_date_snapshot`、`created_at`。

## club_season_enrollment_coach（阶段16B新增）

保存报名教练关系及姓名、职务快照，`enrollment_id + coach_id` 唯一。主要字段：`enrollment_coach_id`、`enrollment_id`、`coach_id`、`coach_name_snapshot`、`title_snapshot`、`created_at`。当前 `coach_info` 没有出生信息，因此阶段16B不计算教练年龄。

## season_schedule_batch（阶段16C新增）

每个赛季最多一条自动排赛批次，通过 `UNIQUE(season_id)` 保证幂等。`batch_status` 仅为 `GENERATED/CONFIRMED`，独立表达赛程审核状态，不复用比赛状态；`trigger_type` 为 `FULL/DEADLINE/MANUAL`。同时保存球队、轮次、比赛数量以及按统一系统时间记录的生成、确认时间和确认人。

## season_schedule_match（阶段16C新增）

关联自动排赛批次与写入 `match_info` 的比赛。`match_id` 全局唯一关联到一个批次，确保能区分自动比赛与人工比赛；批次删除时仅清理关系记录，不以业务接口自动删除比赛。

## ticket_order（阶段10确认补充）

| 字段名 | SQL类型 | 可空 | 主键 | 外键/约束 | 默认值 | 说明 |
|---|---|---|---|---|---|---|
| cancel_reason | VARCHAR(32) | 是 | 否 | Service控制合法值 | NULL | 取消原因；阶段10使用 USER_CANCELLED、PAYMENT_TIMEOUT，未取消时为NULL |

`cancel_reason` 不复用 `remark`。为降低后续新增系统取消原因时的迁移成本，本字段不增加数据库CHECK，由订单Service统一控制。

## order_item（阶段10确认补充）

| 字段名 | SQL类型 | 可空 | 主键 | 外键/约束 | 默认值 | 说明 |
|---|---|---|---|---|---|---|
| item_status | VARCHAR(16) | 否 | 否 | CHECK：LOCKED/PAID/CANCELLED/REFUNDED | LOCKED | 订单明细状态；阶段10仅产生LOCKED和CANCELLED |

完整状态基线为 `LOCKED`、`PAID`、`CANCELLED`、`REFUNDED`。阶段10创建订单写入 `LOCKED`，用户取消或支付超时执行 `LOCKED → CANCELLED`；`PAID` 和 `REFUNDED` 分别留待支付、退票阶段实现。
